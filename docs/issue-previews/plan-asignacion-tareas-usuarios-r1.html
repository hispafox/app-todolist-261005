## Objetivo
Resolver y documentar las decisiones de producto que determinan el contrato de asignación de usuarios a tareas, sin convertir las recomendaciones del plan en requisitos aprobados.

## Origen
Plan: `docs/plan-asignacion-tareas-usuarios.md`
Secciones: “Decisiones pendientes antes de implementar” y paso 1 de “Secuencia propuesta”.

## Alcance

- Confirmar la fuente del selector: un directorio/API existente y su contrato, o un catálogo local mínimo aprobado explícitamente.
- Confirmar si la asignación se podrá cambiar y quitar desde la edición.
- Confirmar qué debe ocurrir al eliminar un usuario asignado y si se incorpora una operación de borrado de usuarios.

## Fuera de alcance
- Implementar modelo, migraciones, API o interfaz.
- Añadir autenticación, credenciales, roles o gestión de usuarios no aprobada.
- Tratar las recomendaciones del plan como decisiones ya tomadas.

- [ ] Registrar si se puede cambiar/quitar la asignación.

## Objetivo
Permitir seleccionar y visualizar el usuario asignado a una tarea, conservar la asignación en SQLite y rechazar referencias a usuarios inexistentes, conforme a las decisiones confirmadas en I1.

## Origen
Plan: `docs/plan-asignacion-tareas-usuarios.md`
Secciones: requisitos confirmados, alcance técnico previsto, frontend, documentación y pruebas, y validación prevista.

## Alcance
- Extender el modelo, la persistencia SQLite/EF Core y la API de tareas con la referencia a usuario, conforme a la opcionalidad y fuente acordadas en I1.
- Crear la migración necesaria sin perder tareas existentes y aplicando la estrategia acordada para asignaciones existentes.
- Validar usuarios inexistentes y devolver un error claro; las respuestas de lectura y mutación deben incluir los datos acordados para mostrar la asignación.
- Cargar las opciones de usuario desde la fuente aprobada, permitir asignar y mostrar al usuario según el contrato final y las decisiones de I1.
- Implementar cambio o retirada de la asignación y el comportamiento de eliminación de usuarios solo según lo aprobado en I1.
- Actualizar el análisis/diseño y las pruebas relacionadas.

## Fuera de alcance
- Autenticación, credenciales, roles o gestión general de usuarios, salvo las operaciones mínimas aprobadas para la fuente del selector.
- Asignar varios usuarios a una misma tarea.
- Cambios no relacionados a tareas o categorías.

## Trabajo
- [ ] Implementar el modelo, la configuración EF Core y la migración preservando las tareas existentes conforme a la decisión de I1.
- [ ] Extender los contratos y operaciones de la API, incluyendo la validación de existencia y los datos de usuario en las respuestas pertinentes.
- [ ] Integrar la fuente aprobada y el selector en alta/edición, mostrar la asignación y reflejar errores sin simular un guardado exitoso.
- [ ] Aplicar las reglas acordadas para cambiar, quitar y eliminar asignaciones/usuarios.
- [ ] Actualizar documentación y pruebas de backend/API y frontend pertinentes.

## Criterios de aceptación
- [ ] Una tarea conserva su asignación al guardarse, consultarse y recargar la aplicación; las respuestas reflejan la asignación persistida.
- [ ] Crear o editar con un identificador de usuario inexistente devuelve un error 400 claro y no persiste cambios parciales.
- [ ] Las tareas existentes y las operaciones actuales de tareas y categorías siguen funcionando según las decisiones aprobadas.
- [ ] La interfaz permite seleccionar y visualizar el usuario; las acciones de cambio/retirada coinciden con el contrato aprobado.
- [ ] Las reglas de eliminación acordadas protegen las tareas asignadas sin borrados o reasignaciones implícitas.
- [ ] Las pruebas dirigidas y la compilación de producción del frontend pasan.

## Validación
- Probar persistencia y lectura de una tarea asignada; probar usuario inexistente al crear y editar sin cambios parciales.
- Probar migración sobre tareas existentes y el comportamiento de cambiar, quitar o eliminar asignaciones que se haya aprobado.
- Verificar que completar/eliminar tareas y las operaciones de categorías no pierden ni alteran asignaciones de forma inesperada.
- Verificar carga/visualización del selector, feedback de fallos y build de producción de Vite/TypeScript.
